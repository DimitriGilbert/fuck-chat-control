# Protocol v1 Specification

This is the frozen wire and cryptographic protocol specification for
v1. It is the single source of truth for the canonical codec, the
crypto module, framing, and the orchestrator. Changes here require a
new ADR.

Authentication in v1 is **safety-number-only**; there is no PAKE. See
[ADR 001](../adr/001-crypto-dependencies.md) and the
[threat model](threat-model.md).

## 1. Versioning

| Constant              | Value  | Where                                                         |
| --------------------- | ------ | ------------------------------------------------------------- |
| Protocol version byte | `0x01` | First byte of the transcript and of every frame header / AAD. |
| Transcript version    | `0x01` | First byte of the canonical transcript encoding.              |
| Export-bundle version | `1`    | Integer in the JSON envelope's `v` field.                     |

An unknown version byte on the wire is a terminal protocol error.
Receivers MUST NOT attempt forward-compatible parsing of an unknown
version.

All multi-byte integers are **big-endian, unsigned, fixed-width**.
There are no length-prefixed varints in the canonical encodings;
lengths are implicit in the type where fixed, and explicit as a
fixed-width `uint32` where variable (ciphertext length only).

## 2. Primitive encodings

### 2.1 P-256 public key — uncompressed SEC1, 65 bytes

A public key is the raw uncompressed SEC1 encoding:

```
0x04 || X(32 bytes, big-endian) || Y(32 bytes, big-endian)   = 65 bytes total
```

- The leading byte MUST be `0x04`.
- Compressed encodings (`0x02` / `0x03`) are NOT accepted in v1.
- The point MUST lie on the P-256 curve (`secp256r1`). Validation is
  performed by the codec via `@noble/curves` before a key is accepted
  into any typed value.
- Reference: SEC 1: Elliptic Curve Cryptography, §2.3.3 ( uncompressed
  point encoding), §3.2.1 (point validation). Equivalent to NIST
  SP 800-186 §3.2.1 and X9.62 §4.3.6.

### 2.2 ECDSA signature — IEEE P1363 (`r || s`), 64 bytes

A signature is the fixed-width concatenation of the two integer halves,
each exactly 32 bytes big-endian, zero-padded on the left:

```
r(32 bytes, big-endian) || s(32 bytes, big-endian)   = 64 bytes total
```

- DER-encoded signatures (`ASN.1 SEQUENCE`) are NOT accepted in v1.
- Reference: IEEE P1363, §5.6.2 (signature encoding, `r||s`). Equivalent
  to RFC 8032's "raw" r||s convention for fixed-width curves and to the
  WebCrypto `ecdsa` `raw` signature format for P-256.

### 2.3 Conversation ID — 16 bytes (128 bits)

Opaque bearer rendezvous handle. CSPRNG-generated by the initiator,
exactly 16 bytes, validated strictly on the broker and by the codec.
Carried in the URL fragment; never in an HTTP request path or query.

### 2.4 Session ID — 32 bytes (256 bits)

Random per-peer, per-connection value. Each peer contributes one
session ID at handshake time. Both session IDs are bound into the
transcript. The sender's session ID is carried in every frame's AAD and
drives deterministic per-direction nonce derivation (§5). The receiver
keeps a replay window keyed by `(sender_role, sender_session_id)`.

## 3. Role derivation

Roles are derived **deterministically** from the two peers' identity
public keys, never from broker messages.

1. Encode both peers' identity public keys as 65-byte uncompressed SEC1.
2. Compare the two byte strings lexicographically (unsigned byte-wise,
   shortest-unequal wins; equal length compares element-wise from
   offset 0).
3. The peer whose identity public key bytes are **lexicographically
   smaller** is the **Initiator**. The other peer is the **Responder**.
4. The transcript records keys and session IDs in canonical
   `(initiator, responder)` order, so the role is implicit in a
   well-formed transcript.

Tie-breaker (defensive, normally impossible): if the two identity
public key byte strings are equal, the peers share an identity key,
which means a device is attempting to talk to itself. This is a fatal
protocol error (`RoleIndeterminable`); no session is established.

### Perfect-negotiation collision policy (simultaneous rejoin)

When both peers rejoin the broker room for the same conversation at the
same time, both may emit a WebRTC offer ("glare"). Roles are already
fixed cryptographically (above), so the glare is resolved
deterministically by the perfect-negotiation pattern:

- The **Initiator is the impolite peer**: on glare, it keeps its offer
  and proceeds.
- The **Responder is the polite peer**: on glare, it rolls back its
  local description and answers the initiator's offer.

This guarantees forward progress without any broker-mediated role
message. Broker-originated role assertions are never trusted for
cryptographic identity or authentication.

## 4. HKDF labels and key schedule

The traffic key schedule derives from the ECDH shared secret and the
SHA-256 hash of the canonical transcript (§6).

```
prk        = HKDF-Extract(salt = transcript_hash, IKM = ecdh_secret)
init_key   = HKDF-Expand(prk, L = 32, info = Label("fck-chat-v1/init->resp/traffic"))
resp_key   = HKDF-Expand(prk, L = 32, info = Label("fck-chat-v1/resp->init/traffic"))
base_nonce = HKDF-Expand(prk, L = 12, info = Label("fck-chat-v1/nonce-base"))
```

Where `Label(s)` is the ASCII bytes of `s` with no trailing NUL.

- `init_key` encrypts frames sent by the initiator and is decrypted by
  the responder. `resp_key` encrypts frames sent by the responder and
  is decrypted by the initiator. Directional labels prevent reflection
  and key/nonce reuse across directions.
- `base_nonce` is shared by both directions (see §5 for why this is
  safe). Deriving it from the transcript hash means a fresh nonce
  space on every session, including resumption.

HKDF is RFC 5869 with SHA-256.

## 5. Per-direction nonce derivation

The AEAD nonce is **96 bits (12 bytes)**, constructed from the sender's
session ID and the frame sequence number:

```
nonce = sender_session_id[0..12]  XOR  seq12
```

where `seq12` is the sender sequence number encoded as a **12-byte
big-endian unsigned integer** (the `uint32` sequence value zero-padded
on the left to 12 bytes).

- Because the sender session ID differs per direction (each peer
  contributes its own), the two directions have disjoint nonce spaces
  even with the same `base_nonce`-free derivation. Directional keys
  (`init_key`, `resp_key`) make this belt-and-suspenders.
- Because the sequence number is monotonically increasing within a
  session and the sender stops before the `uint32` space is exhausted,
  a nonce never repeats under one `(sender_session_id, key)` pair.
- This construction is deterministic and stateless on the sender side
  given `(session_id, sequence)`, and trivially verifiable on the
  receiver side, so the receiver can reject a repeated nonce/sequence
  via the replay window without decrypting.

The `base_nonce` HKDF output in §4 is reserved for future
counter-mode nonce bases; v1 transport uses the session-ID-XOR
construction above exclusively.

## 6. Canonical transcript

The transcript is a single canonical byte string over which both peers
compute the SHA-256 hash that binds the handshake and feeds the key
schedule. Fields are concatenated in the exact order below with no
length prefixes (all widths are fixed). Roles are already canonical, so
all fields appear in `(initiator, responder)` order.

| Offset | Width (B) | Field                         | Encoding                    |
| ------ | --------- | ----------------------------- | --------------------------- |
| 0      | 1         | transcript version            | `0x01`                      |
| 1      | 1         | protocol version              | `0x01`                      |
| 2      | 16        | conversation ID               | raw                         |
| 18     | 1         | authentication mode           | `0x01` = `SafetyNumberOnly` |
| 19     | 65        | initiator identity public key | SEC1 uncompressed           |
| 84     | 65        | responder identity public key | SEC1 uncompressed           |
| 149    | 65        | initiator ephemeral ECDH key  | SEC1 uncompressed           |
| 214    | 65        | responder ephemeral ECDH key  | SEC1 uncompressed           |
| 279    | 32        | initiator session ID          | raw                         |
| 311    | 32        | responder session ID          | raw                         |

Total: **343 bytes**. The transcript hash is `SHA-256(transcript)`.

Identity signatures are computed as ECDSA-P-256 over the SHA-256 hash
of the transcript, encoded per §2.2 (`r || s`, 64 bytes). Each peer
signs with its own identity private key and verifies the peer's
signature against the peer's identity public key (TOFU on first
contact; match against stored key on resumption).

## 7. Frame format and AAD

A v1 frame on the wire is:

```
FrameHeader || nonce(12) || ciphertext(ciphertextLength)
```

Per-frame authentication is provided by the AES-256-GCM tag embedded in
`ciphertext`; peer-identity authentication is bound once at handshake via
the transcript signature (§6).

### 7.1 Frame header (and authenticated additional data)

The FrameHeader carries the per-frame metadata. The authenticated
additional data (AAD) for AES-GCM is the FrameHeader **without** the
trailing `ciphertextLength` field. Lengths are fixed-width big-endian.

FrameHeader fields, in canonical order:

| Width (B) | Field             | Encoding / notes                                         |
| --------- | ----------------- | -------------------------------------------------------- |
| 1         | protocol version  | `0x01`                                                   |
| 32        | sender session ID | raw, identifies the sender's nonce/replay space          |
| 4         | sender sequence   | uint32 BE, monotonically increasing within the session   |
| 1         | frame type        | enum (§8)                                                |
| 4         | transfer ID       | uint32 BE, `0` when the frame is not part of a transfer  |
| 4         | chunk ID          | uint32 BE, `0` when the frame is not a chunk             |
| 4         | ciphertext length | uint32 BE, length of the `ciphertext` field that follows |

FrameHeader size: **50 bytes**. AAD size: **46 bytes** (everything but
`ciphertextLength`).

The codec validates, in order: protocol version, frame type enum,
sequence range, transfer/chunk ID relationships per frame type, and
`ciphertextLength` against the limit for the frame type — **all before**
the ciphertext buffer is allocated.

### 7.2 Frame type enum

| Value  | Name             | Transfer/Chunk IDs         | Ciphertext payload cap                         |
| ------ | ---------------- | -------------------------- | ---------------------------------------------- |
| `0x01` | `text`           | both `0`                   | `MAX_TEXT_FRAME_BYTES` (16384)                 |
| `0x02` | `file_manifest`  | transfer ID set, chunk `0` | `MAX_TEXT_FRAME_BYTES` (manifest envelope cap) |
| `0x03` | `file_chunk`     | transfer + chunk IDs set   | `MAX_CHUNK_BYTES` (16384)                      |
| `0x04` | `control`        | both `0`                   | `MAX_TEXT_FRAME_BYTES` (control envelope cap)  |
| `0x05` | `media_manifest` | transfer ID set, chunk `0` | reserved, NOT implemented in v1                |
| `0x06` | `media_chunk`    | transfer + chunk IDs set   | reserved, NOT implemented in v1                |

Any other frame type value is a terminal protocol error. Reserved media
types (`0x05`, `0x06`) are typed so future work does not need to break
the enum, but they are rejected by the v1 transport.

### 7.3 Control subtypes

For `frame_type = 0x04 control`, the first byte of the decrypted
plaintext is the control subtype:

| Value  | Name                         |
| ------ | ---------------------------- |
| `0x01` | `session_key_exchange`       |
| `0x02` | `identity_announcement`      |
| `0x03` | `leave`                      |
| `0x04` | `safety_number_announcement` |

PAKE-related subtypes are removed from v1. Any other control subtype
value is a terminal protocol error.

## 8. Hard limits

These are the frozen v1 limits, exposed as `readonly` constants in
`limits.ts`. Every decoder validates against the relevant limit before
allocating a payload buffer.

| Constant                        | Value        | Meaning                                                               |
| ------------------------------- | ------------ | --------------------------------------------------------------------- |
| `PROTOCOL_VERSION`              | `0x01`       | Wire protocol version byte.                                           |
| `TRANSCRIPT_VERSION`            | `0x01`       | Canonical transcript version byte.                                    |
| `EXPORT_BUNDLE_VERSION`         | `1`          | Export/import JSON envelope `v` field.                                |
| `CONVERSATION_ID_BYTES`         | `16`         | Conversation / room ID length (128 bits).                             |
| `SESSION_ID_BYTES`              | `32`         | Per-peer session ID length (256 bits).                                |
| `PUBLIC_KEY_BYTES`              | `65`         | Uncompressed SEC1 P-256 public key length.                            |
| `SIGNATURE_BYTES`               | `64`         | IEEE-P1363 P-256 signature length.                                    |
| `MAX_SEQUENCE`                  | `4294967295` | Maximum sender sequence (`2^32 - 1`); sender stops at it.             |
| `MAX_TEXT_FRAME_BYTES`          | `16384`      | Codec cap on a `text`/manifest/control frame's wire payload (16 KiB). |
| `MAX_CHUNK_BYTES`               | `16384`      | Codec cap on a `file_chunk`/`media_chunk` wire payload (16 KiB).      |
| `MAX_MANIFEST_NAME_BYTES`       | `255`        | Maximum file name byte length in a manifest.                          |
| `MAX_MANIFEST_MIME_BYTES`       | `127`        | Maximum MIME type byte length in a manifest.                          |
| `MAX_MANIFEST_SIZE_BYTES`       | `4294967295` | Maximum declared file size (`2^32 - 1`, uint32).                      |
| `MAX_CONCURRENT_TRANSFERS`      | `4`          | Maximum simultaneous active transfers per conversation.               |
| `MAX_INCOMPLETE_TRANSFER_BYTES` | `67108864`   | Maximum sum of incomplete-transfer buffered bytes (64 MiB).           |
| `MAX_BUFFERED_DATA_BYTES`       | `1048576`    | Maximum total buffered data backpressure cap (1 MiB).                 |
| `REPLAY_WINDOW_SEQUENCES`       | `1024`       | Bounded replay window size per `(sender, session)`.                   |
| `HANDSHAKE_TIMEOUT_MS`          | `30000`      | Maximum handshake duration (30 s).                                    |
| `FRAME_PARSE_TIMEOUT_MS`        | `5000`       | Maximum time to parse/validate one frame (5 s).                       |

`MAX_SEQUENCE` is the largest representable `uint32`; the sender MUST
stop and tear down before sending a frame whose sequence would exceed
it, so the nonce space is never wrapped.

## 9. Export / import bundle

The export/import bundle is a versioned JSON envelope. All binary
fields are base64 (standard, padded) of their raw byte form.

```json
{
  "v": 1,
  "kdf": {
    "algorithm": "argon2id",
    "version": 19,
    "m": 67108864,
    "t": 3,
    "p": 1,
    "salt": "<base64, 16 bytes>"
  },
  "aead": {
    "algorithm": "aes-256-gcm",
    "nonce": "<base64, 12 bytes>"
  },
  "ciphertext": "<base64>"
}
```

- `kdf.algorithm` is exactly `"argon2id"`; `kdf.version` is the Argon2
  algorithm version `19` (`0x13`).
- `m` (memory in bytes), `t` (iterations), `p` (parallelism), and the
  16-byte `salt` are frozen at bundle creation time and recorded so an
  importer can re-derive the key without negotiation.
- `aead.nonce` is the 12-byte AES-256-GCM nonce used for the bundle.
- `ciphertext` is the AEAD output (ciphertext || 16-byte tag) over the
  canonical inner payload (identity private key + serialized history).
- Unknown envelope fields are ignored by the importer; a missing or
  unsupported `v`, `kdf.algorithm`, or `aead.algorithm` is a terminal
  import error.

Argon2id parameters (default): `m = 67108864` (64 MiB), `t = 3`, `p = 1`.
These run off the main thread (Web Worker) to avoid blocking the UI;
revisiting them requires a new ADR.

## 10. Wire-level parsing invariants

These are non-negotiable properties of the canonical codec:

1. **Validate before allocate.** Every decoder checks lengths,
   versions, and enum values against fixed constants and limits _before_
   allocating any application-payload buffer. A malformed frame never
   causes unbounded allocation.
2. **No implicit encoding.** Every byte is explicit in the canonical
   order above; there are no length-implied fields, no varints, no
   optional fields inferred by absence.
3. **No mutable transcripts.** Transcript objects are readonly and
   canonical; there is no API to mutate a field without re-encoding.
4. **No caller nonces.** Nonces are derived from `(sender_session_id,
sequence)` (§5); the codec never accepts an external nonce.
5. **Typed errors.** Every malformed input is rejected by throwing a
   `ProtocolError` carrying a stable `code` from the `ProtocolErrorCode`
   enum. Callers branch on the code, not on message text.
